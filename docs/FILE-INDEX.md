# FILE INDEX — KickOff B2B

Every file in the repository, and what was decided about it. The Phase C3
audit was **flow-driven** — it covered the flows and the files they touch — so
roughly half the repository had never been looked at. This index makes the
coverage explicit and keeps it true: a file that is added must be reviewed
before the suite is green again.

- **Enforced by:** `scripts/tests/file-coverage.test.mjs` (FI-1 … FI-7).
- **Kept in step by:** `node scripts/build-file-index.mjs --check` (CI) and
  `--sync` (adds new files as `unreviewed`, so they must be reviewed).
- **Last verified:** 2026-11-15 · **Owner:** engineering
- **Related:** [`FLOW-AUDIT.md`](FLOW-AUDIT.md) (the flow findings) ·
  [`ARCHITECTURE.md`](ARCHITECTURE.md) · [`PLAN.md`](../PLAN.md)

## Verdicts

| Verdict | Meaning |
|---|---|
| `reviewed` | The file was read and judged; the note says what it is or what it carries. |
| `covered` | A test or contract file — its assertions enforce a rule that the review confirmed. |
| `generated` | Machine output. It is regenerated by a command, never edited by hand. |
| `asset` | A media asset. Checked: it is referenced by the app and correctly licensed. |
| `template-leftover` | Boilerplate from a framework template. It is deleted, not kept. |
| `deferred` | Deliberately not reviewed yet — the note states the reason and the follow-up. |
| `unreviewed` | **Not allowed.** A new file starts here and must be reviewed. |

## Kinds

| Kind | Meaning |
|---|---|
| `source` | Application, function or script code. |
| `test` | Tests and contracts. |
| `config` | Configuration, tooling and lock files. |
| `asset` | Images and other media. |
| `doc` | Documentation. |
| `data` | SQL: schema, RLS, RPCs, seeds and pgTAP suites. |
| `license` | Licence files. |

## Reading rules

- One row per tracked file. The path is the repository-relative path.
- A verdict without a note is only acceptable for a self-evident file; a
  `deferred` file **must** carry the reason.
- The index never becomes stale silently: `--check` fails when a tracked file
  is missing from it or when it lists a file that no longer exists.
